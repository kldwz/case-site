# 生产级 Agent 记忆 vs Day7 教学版

> **类型**: concept (Agent 记忆系统 / 学习地图)
> **来源**: 旺旺在 Day7（记忆与检索）学完最小范式后提出的追问 + 讲解梳理
> **采集日**: 2026-08-12
> **关联**: [[entities/ai-bloggers]]、[[concepts/agent-as-daily-sms]]、Day8 上下文工程

## 摘要

Day7 学的是"单库语义检索"最小范式（对话→embedding→向量库→检索 top_k→塞回 prompt），是**对的地基、最小可理解版**，但不是生产全貌。真实生产记忆是分层、带生命周期管理的系统。本文把"教学版 vs 生产级"的差距地图固化下来，标注旺旺还差哪几层。

## 教学版（Day7 已掌握）

```
对话 → embedding → 单向量库 → 检索 top_k → 塞回 prompt
```
- 只覆盖**语义记忆**一种类型
- 只增不删、无分类、无冲突处理
- 每轮无脑检索全部塞回（踩了"塞太多"的坑，引出 Day8）

## 生产级差距（5 个维度）

### 1. 记忆不是一种，是四种并存
| 类型 | 存什么 | 引擎 | 例子 |
|------|--------|------|------|
| 工作记忆 Working | 当前任务临时状态/中间步骤 | 内存/结构化变量 | "用户刚上传3个文件正在对比" |
| 语义记忆 Semantic | 用户稳定事实/偏好 | 向量库（教学版这块） | "旺旺讨厌长会" |
| 情景记忆 Episodic | 过去特定事件/会话 | 向量+时间索引 | "上周帮他搭了电商Agent" |
| 程序性记忆 Procedural | "怎么做事"的套路 | 技能/SOP/提示词库 | "退款处理标准流程" |

### 2. 不是全塞回，而是"按需调取 + 结构化"
- 写入时：分类、打标签、去重、**冲突消解**（前后矛盾要合并非并存）
- 读取时：按"当前任务需要哪种记忆"定向取，而非无脑 top_k
- 自动**压缩/老化**：旧低价值记忆摘要或降权

### 3. 写冲突与遗忘机制（教学版缺失）
- 矛盾处理：用户说"不喝咖啡了" vs 之前"爱喝咖啡" → 更新非并存
- 遗忘/老化：3 个月前临时上下文该清
- 隐私与权限：哪些跨会话保留、哪些仅本次

### 4. 长程任务不能只靠记忆库硬塞
- Checkpoint / 状态快照（卡住能恢复）
- 结构化记忆（JSON/表格）而非纯文本，方便程序读取
- 多智能体时每个 Agent 有隔离记忆空间

### 5. 工程化能力（未碰）
- 记忆质量评估（检索准不准、是否泄露无关信息）
- 成本控制（检索自身花钱、占延迟）
- 可观测（哪条记忆影响本次决策，可回溯）

## 真实参照
- **Mem0 本身**已比 Day7 复杂：多类型（fact/event/procedure）、自动提取、冲突更新、可接图数据库做实体关系。本地部署只是单用户最小用法。
- **大厂 Agent**：向量库 + KV 结构化状态 + 定时压缩摘要 + 检索重排组合；常把长对话定期喂小模型做"记忆提炼"存成结构化 profile。
- **前沿**：记忆做成可查询工具（Agent 自己决定"现在该查关于此用户的什么记忆"），而非被动每次全注入。

## 易错点钉死
1. "塞得越多越好"是反直觉坑——窗口塞满反而掉分（lost-in-the-middle：模型忽视中间内容）。
2. **记忆 ≠ 上下文**：记忆在外部（Mem0），上下文是"当前这轮真正喂给模型的那段"，两者通过"检索+裁剪"桥接。
3. 压缩会丢信息：摘要不能无限压，关键事实（名字/偏好/约束）要保底保留。

## 和旺旺路线的接法
- **短期**（一人公司 / AI 教学 + 工具）：用现有 Mem0 单库语义记忆**完全够用**，别被生产级复杂度吓到。
- **做真有人用的 Agent 产品时**再补：① 记忆分类（至少 working/semantic）② 写入去重+冲突更新 ③ 上下文裁剪（= Day8）。

## 与 Day8 的关系
Day8 上下文工程是"记忆/知识有了，但怎么塞进窗口才不出事"——是**从教学版迈向生产可用的第一块拼图**，解决 Day7 那个"捞回几十条全塞"的坑。
