# Mochi：只有一个前端三件套，却拿下了"最佳真实世界应用"

## 产品是什么

一个 Chrome 扩展：把网页上难读的内容自动改写得更好读——给阅读障碍（dyslexia）、ADHD 用户，以及所有读长文费劲的人。

技术栈干净到有点过分：**HTML + CSS + JavaScript**，加上 Chrome 内置的 AI 模型。没有后端，没有 API 费用。

## 它解决了什么

互联网上的大部分内容都是为「阅读能力正常」的人写的。对有阅读障碍的人来说，密密麻麻的文字不是「费点劲」，而是「根本读不下去」。

现有的辅助工具要么要装软件、要么要付费、要么要手动复制粘贴到别的工具里处理。Mochi 的做法是：**在你正在看的网页上直接改写**。

## 这个解法妙在哪

1. **用浏览器内置 AI 省掉了整个后端**。Chrome 自带模型，不调外部 API、不花 token、不上传数据——成本、延迟、隐私三个问题一次性解决。
2. **复杂度不在技术，在选题**。纯前端三件套拿奖，说明评委看的是「这东西有没有真的帮到人」，而不是架构多复杂。
3. **名字即解释**。Mochi（麻薯）软糯好入口，正好对应「把硬邦邦的内容变软」——产品名本身就是最省事的说明书。
4. **受益人群说得清**。阅读障碍、ADHD、失读症，不是虚构的用户画像，是有明确诊断标准的真实人群。

## 团队与赛事

独立开发者 Han Wei Tan，提交于 **Google Chrome Built-in AI Challenge**（谷歌官方赛事，googlechromeai.devpost.com），获 **Winner · Best 'Real-World' App (Chrome Extension)**，109 个赞。

## 这个案例能学到什么

① **选「受益人说得清」的场景**。需求真实、人群明确、长期被忽视——这三点叠在一起就是好选题。

② **平台内置的 AI 是免费午餐**。浏览器/系统自带模型能省掉后端、成本和隐私问题，是当下最被低估的机会。

③ **技术复杂度不等于价值**。HTML/CSS/JS 也能拿最佳应用奖，评委看的是「有没有真的解决真问题」。

④ **产品名可以承担解释功能**。「Mochi」四个字母就把「把内容变软」讲完了。

⑤ **无障碍是小而稳的赛道**：用户极度忠诚、竞争者极少、社会价值天然可讲。
