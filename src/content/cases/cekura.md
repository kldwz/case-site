# Cekura：三个人给自己做的语音 agent 做测试，做成了 75 家客户的生意

## 产品是什么

**Cekura** 是给**对话式 AI agent（语音和聊天）**做自动化测试与监控的平台。简单说：**在你的语音机器人上生产环境之前，先用几千通模拟电话把它骂一遍。**

平台覆盖 agent 的整个生命周期——**上线前仿真、生产监控、对抗测试**：

- **大规模仿真**：按自定义或 AI 生成的数据集、工作流和动态人设，跑出成千上万通真实场景对话——点餐、预约、面试、催收
- **合成用户**：模拟真人跟 agent 对话，覆盖各种口音、背景噪音、犹豫停顿、语速差异，包括慢吞吞的、爱打断的、非母语者，以及自定义克隆声音
- **AI 生成评估指标**：追踪指令遵循、工具调用，以及打断率、延迟这类对话指标
- **红队对抗测试**：几分钟内跑完几千次对抗模拟，模拟提示注入攻击，看 agent 会不会无视指令、泄露系统提示词；检查金融、医疗、招聘建议里的隐藏偏见；尝试激怒 agent 说出不专业或冒犯的话；试图套出信用卡号、内部密钥

Cekura 直接拿行业数据当销售素材：**Gartner 预计到 2027 年底超过 40% 的 agentic AI 项目会因为成本失控、价值不明确或风控不足而失败或被砍掉；OWASP 2025 报告显示接受安全审计的生产 AI 部署中，超过 73% 存在提示注入漏洞。**

## 怎么赚的钱

SaaS 订阅 + 按用量计费，客户分布在医疗、银行、物流、招聘、零售这些**合规压力最大**的行业。

融资与规模：

- 2024-08 入选 **Y Combinator F24** 批次
- 2025-07 种子轮 **240 万美元**
- 客户 **75 家以上**，不乏 Five9、PwC、Deloitte、Twin Health、Lindy 这样的名字
- 团队 **15 人**

⚠️ 营收绝对值未获官方确认。第三方数据库曾记录 2025 年中约 66 万美元营收，属估算，不作为硬数据采信。

## 流量从哪来

1. **产品来自自己踩过的坑**。创始团队此前自己做过医疗语音助手，为了测试，**几个人连续几周手动拨号进去测**，结果**仍然有一个致命故障漏到了真实通话里**。这个失败直接催生了公司——**你亲手被同一个问题折磨过，才知道该做什么**。

2. **Agent 越多，验证越刚需**。Gartner 说 40% 的 agent 项目会在 2027 年前死掉；LangChain 的调研里三分之一的从业者说质量是上生产的最大障碍。**别人都在卖铲子，你卖质检，是更稳的位置。**

3. **绑定 ATS 平台做渠道**。2025 年 12 月，Cekura 宣布为招聘平台 **Gem** 提供求职者欺诈检测，直接嵌进客户从 sourcing 到录用的流程里。**一次集成，换来 Gem 背后几千家雇主。**

4. **红队测试天然自带传播性**。「我们让 agent 泄露了信用卡号」这种 demo，比任何功能介绍都容易被转发。**把产品的输出物做成可传播的内容。**

5. **合规行业不敢省这笔钱**。医疗、金融、招聘一旦出事就是监管问题——**在客户「不敢不做」的环节收费，比在「做了更好」的环节收费容易得多。**

- **Shashij Gupta（CTO / 产品负责人）**：曾在 Google Research 做 NLP 研究，在苏黎世联邦理工（ETH Zurich）期间以第一作者发表过测试 transformer 的论文，被引 50 次以上；IIT Bombay 与 ETH Zurich 背景
- **Sidhant Kabra（总裁）**：咨询背景，给财富 500 强 CEO 做过顾问，带过 100 人以上的客户体验团队，曾在一家教育科技公司负责产品与增长，**六个月内把用户从 0 做到 20 万以上**

这个配置很典型：**一个懂钱、一个懂模型、一个懂交付**。

## 这个案例能学到什么

第一，**最好的点子来自自己踩过的坑**。他们人工拨号测了几周还是漏了 bug——这个挫败感比任何市场调研都准。**创业选题最可靠的来源，是你自己反复撞上的那堵墙。**

第二，**淘金热里卖质检，比淘金稳**。所有人都在做 agent，但 Gartner 说 40% 会死。**当某个品类大量涌现时，围绕它的「验证、监控、合规」是确定性更高的机会。**

第三，**挑客户「不敢不做」的环节收费**。医疗、金融、招聘出错要担监管责任，预算是刚性的。**卖止痛药比卖维生素容易。**

第四，**把产品输出物做成传播素材**。红队测试的产出天然就是好内容——「看，我们骗它把系统提示词念出来了」。**你的产品如果能自动生成可分享的东西，营销成本会低一个数量级。**

第五，**早期三人组要覆盖三条线**。CEO 懂钱、CTO 懂技术、总裁懂交付与增长——**技术、研究、商务各占一块，比三个都会写代码的强。**
