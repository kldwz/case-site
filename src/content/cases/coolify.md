# Coolify：一个人做的开源 PaaS，6.1 万星换来 50 万个自建实例

## 产品是什么

Coolify 是一台装在自己服务器上的部署引擎。你把一台机器的 SSH 交给它，它就把静态站、数据库、全栈应用，以及 280+ 个一键服务装上去、跑起来、挂上 HTTPS 证书、定时备份到对象存储——"git push 就上线"的体验，账单只有那台服务器的钱。

它对标的对象写在仓库描述里：**Vercel、Heroku、Netlify、Railway 的开源自托管替代品**。

仓库数据：**61,717 star、5,452 fork**，用 PHP（Laravel）写，2021 年 1 月 25 日创建，Apache-2.0 许可。

它精准吃的是那波情绪：PaaS 本来是让开发者"别管服务器"的，十年下来变成了订阅制——免费层不断缩水，生产环境上来就要 Pro 席位费，流量再单独计价。一个手里跑着五六个副业项目的人，月末账单常常比服务器本身还贵。

## 怎么赚的钱

**自托管永久免费，云版 5 美金一个月起。**

官方定价页把两种方案并排贴出来，功能表几乎逐行相同，差异只在"谁来干运维这些活"：

| | 自托管 | Cloud |
|---|---|---|
| 价格 | 永久免费 | $5/月起（含 2 台服务器，每加 1 台 +$3/月，年付省 20%） |
| 功能 | 全部功能，无限制 | 全部功能 |
| 代码 | 开源 | 同一个开源代码库 |
| 托管、备份、更新、告警 | 自己配（可自动化） | Coolify 帮你管 |
| 控制台域名 | 自定义 | app.coolify.io |

注意两个细节。

**第一，付费买的是省心，不是功能。** 你的应用始终跑在你自己的服务器上，Coolify 只是把"部署、备份、监控、更新、告警"这些运维活接过去。这跟"免费版砍功能、付费解锁"的路子完全不同。

**第二，价格跟服务器台数挂钩，不跟人挂钩。** 团队人数和成员数都不限，多招人不会涨账单——这个设计直接对准了按席位收费的商业 PaaS。

收入官方没披露。能查到的是规模：官网首页展示**云端客户 3,765+、自托管实例 505,437+**，Discord 社区 21k+ 成员。

## 流量从哪来

- **一行安装命令**。官方给的入口就是 `curl -fsSL .../install.sh | bash`，从看到项目到跑起来不到五分钟，转化路径短到没有摩擦；
- **对涨价不满的迁移潮**。Heroku 2022 年砍免费层、Vercel 账单随流量失控、按席位收费越滚越大——每一次这类事件都会把一批人推到"我自己搭一个"的搜索里，Coolify 是那个搜索结果里最响的答案；
- **GitHub 趋势榜与社区**。6 万 star 的仓库本身就是最好的广告位，加上 Discord 里 2 万多人互相答疑，用户的问题基本能在社区里自己解决；
- **创始人亲自下场**。提交记录、issue 回复、release 说明全是同一个账号，用户知道该找谁，也知道这东西不会突然没人管。

## 站长是谁

**Andras Bacsai**，匈牙利 Székesfehérvár 人。他的 GitHub 简介写着：coolLabs.io 创始人、热爱开源与简洁、两个孩子的父亲、创业者。账号 2013 年就注册了（2013-11-03），到今天 1,848 个关注者、61 个公开仓库。

**为什么是他做成**：因为他自己就是那个被账单逼急的用户。Coolify 的每一个设计选择——自托管免费、按服务器不按席位、功能表不做阉割——都对应着一个独立开发者在商业 PaaS 上被收过的钱。这种"我就是目标客户"的项目，卖点不需要市场调研，痛点直接从自己的账单里长出来。

顺带一提，这个案例里最能说明问题的是：**6.1 万 star 的开源基础设施项目，主要维护者是一个人的 GitHub 账号。** 一个人 + 一个清晰的对标对象，也能做成开发者圈子里绕不开的工具。

## 这个案例能学到什么

① **免费版别阉割功能**。自托管和云版功能表逐行相同，用户推荐时才不用加"但是免费版不能……"这句限定语，口碑传播的损耗最小。

② **收费点选在"省心"而不是"功能"**。运维、备份、监控、更新是人人想外包的活，把它做成付费项，用户不会觉得自己被卡脖子。

③ **计价单位决定你得罪谁**。按服务器收费，团队扩张不涨账单；按席位收费，招人就要多付钱。选哪个计价单位，等于选哪一类客户站在你这边。

④ **一个能复述的定位顶过十页功能介绍**。"开源版 Vercel"这五个字传播起来不需要成本，而"可自托管的下一代部署编排平台"需要解释。

⑤ **创始人实名可查就是信任状**。提交记录、issue、release 全在一个账号下，用户能看到谁在维护、多久没动过，这对基础设施类项目比宣传稿管用。
