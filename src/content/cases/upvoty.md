# Upvoty：一个投票板如何长成「产品决策系统」

## 产品是什么

Upvoty 做的是**用户反馈管理**，但它不是「放个投票板就完了」，而是把从想法到上线的四步全串起来：

- **Collect（收集）**：可定制的反馈板，用户能提交需求、bug、想法，带投票、标签、筛选
- **Prioritize（排序）**：按「用户分层 + 账户价值 + 投票速度」算需求热度，而不是单纯按票数
- **Ship（发布）**：更新日志，每次发布自动通知投过票的人
- **Sync（同步）**：推送到 Slack、Jira、Intercom、Zapier

排序这层是它和「普通投票板」的分水岭。官网原话是：按收入或账户等级切分需求，让工程师把精力花在真正有影响的请求上。它还带 **Merge AI** 做重复需求合并——投票板做久了最致命的问题就是一堆重复帖子。

**AI 这步做得很聪明。** Upvoty 提供了 **MCP server**，可以直接接进 ChatGPT、Claude、Gemini、Grok、Perplexity、Cursor。官网演示的场景是你在编辑器里问一句「本月付费客户最想要的前 5 个功能是什么」，它直接回：

```
1. Dark mode for the dashboard - 284 votes
2. Slack notifications - 192 votes
3. CSV export - 147 votes
4. Custom domains - 121 votes
5. API webhooks - 98 votes
```

**反馈看板最大的敌人是「没人打开」。** 把它塞进 AI 对话框，等于把「主动登录看板」变成了「在干活的地方顺口问一句」。

## 怎么赚的钱

订阅制 SaaS，14 天试用、不用信用卡。TrustMRR 上授权同步的数据：

- **MRR 约 4.22 万美元**，累计营收约 **142.1 万美元**
- 付费客户 **1111 个**，当月新增 111 个、流失 42 个
- **月流失率 3.8%**，月增长率 **12.7%**
- 客单价约 **38 美元/月**，客户终身价值约 1000 美元

**1000 多个付费客户、月流失率不到 4%** —— 这是这组数字里最有分量的两个。对工具类 SaaS 来说，3.8% 的月流失意味着平均客户生命周期超过两年，**产品已经过了「靠新客撑增长」的阶段，进入了存量复利区。**

## 这个案例能学到什么

第一，**把单点工具做成闭环，客单价才上得去**。只做投票板，用户随时能换；做成「收集—排序—发布—同步」，它就嵌进了团队的研发流程。**替换成本，才是定价权的来源。**

第二，**AI 的正确用法是补留存短板，不是加功能**。Upvoty 没有做一个「AI 帮你写更新日志」的花架子，而是把 MCP 接到用户已经在用的 ChatGPT/Claude 里——**哪里没人用，就把入口搬到哪里。**

第三，**让需求排序跟着钱走**。按账户价值加权，而不是单纯数票。**少数大客户的一票，往往比一百个免费用户的一票更值钱，但纯投票制会把这件事搞反。**

第四，**公开路线图本身就是增长引擎**。用户投完票会主动回来看进展，还会把自己的用户拉来投票。**把内部流程开放给用户，你就多了一支免费的推广队。**
