# AI 时代，你的内容都丢在哪了？我用飞书给自己建了个「内容仓库」，183 篇一键搬完

就最近很多朋友问我，旺旺，现在用 AI 写东西是快了，可写完的东西全散在各处，过两天想找就找不到了，有没有一个地方能统一存起来？

这个问题太真实了。

我自己做了个创业案例库，每天往里加案例，加着加着就攒了 183 篇。这些内容有的在本地 Markdown 文件里，有的在网站数据库里，有的在公众号草稿箱里躺尸。

如果是十几篇，倒也还好，大不了手动复制粘贴，一篇篇贴过去，一个下午也就干完了。

但是如果是 **183 篇**，而且每篇都有标题、表格、加粗、引用、列表、来源链接……

手动贴？光是格式错乱就够你喝一壶的。更别提贴完发现排版全崩，标题变成正文、表格变成一堆竖线，真的心态都要炸...

我找了一大圈，试过网盘、试过本地文件夹、也试过一些笔记工具。

网盘能存，但没法检索、没法分享给别人看；本地文件夹能存，但换台电脑就抓瞎；笔记工具能存，但格式一粘贴就散架。

不过好在功夫不负有心人。

我最后选定的方案是：**飞书知识库 + 自己建一个飞书应用，用 API 批量写进去**。

我亲测，183 篇全部写完，**12 分 35 秒，零报错**。而且写进去的是飞书原生的标题、表格、引用块，不是一堆纯文本。

今天这篇文章旺旺就毫无保留的把这套方法分享给你们，并附赠保姆级使用教程。

强烈建议大家收藏好这篇文章，哪天你内容攒到几百篇的时候，直接照着做就行。

## 01 为什么是飞书？

先说为什么选飞书，朋友们别急着看操作，想清楚这个更重要。

现在是 AI 时代，生产内容的成本已经低到可怕了。一篇文章、一份报告、一组数据，几分钟就出来了。

**但内容生产越容易，内容留存就越值钱。**

因为大家都能生产，所以「你攒下来的那些」才是真正的资产。问题在于，你攒在哪？

飞书知识库刚好解决了三个事：

**第一，能检索。** 存进去的内容是全文可搜的，不是一堆文件的文件名。

**第二，能分享。** 你存完可以直接把知识库链接甩给别人，对方打开就能看，排版清清楚楚。这个太关键了——内容存起来不是为了吃灰，是为了发出去。

**第三，能协作。** 你一个人写也行，团队一起往里加也行。

说白了，**网站是给搜索引擎看的，飞书知识库是给人传阅的**。同一批内容，两个出口，这才是完整的打法。

🔗 飞书开放平台：https://open.feishu.cn

## 02 第一步：创建一个属于你自己的应用

这一步是整套流程的入口，也是很多人卡住的地方。

**为什么要建应用？**

因为你想让程序批量帮你写内容，就得有个「身份」。这个身份就是你自己建的应用。别被「应用」两个字吓到，其实就是注册一下，两分钟的事。

**具体操作：**

第一步，打开 https://open.feishu.cn ，用你的飞书账号登录。

第二步，右上角点「开发者后台」，然后点「创建企业自建应用」。

第三步，填个应用名（随便起，比如「我的内容同步助手」），创建完成。

第四步，进到应用详情页，左边找到「凭证与基础信息」，你会看到两个东西：

- **App ID**（长这样：`cli_a9715dd9ac381bd3`）
- **App Secret**（一串随机字符）

**把这两个值复制下来存好**，这就是你后面调用 API 的账号密码。

> ⚠️ 提醒一句：App Secret 相当于密码，千万别发到公开的地方，也别提交到 GitHub 上。我自己的做法是存到一个本地的 `.env` 文件里，用的时候再读取。

## 03 第二步：开权限 + 发布版本（很多人漏了这步）

拿到账号密码还不够，你还得明确告诉飞书：这个应用**能干什么**。

**具体操作：**

第一步，在应用后台左侧点「权限管理」。

第二步，搜索并开通这两个权限：

- `docx:document` —— 创建和编辑云文档（这是让你能写内容）
- `wiki:wiki` —— 创建和编辑知识库节点（这是让你能在知识库里建页面）

第三步，点左边的「版本管理与发布」，创建一个版本，提交申请。

第四步，让你企业的飞书管理员审批通过。

> 这一步我踩过坑：光拿到 App ID 和 Secret 不代表权限开通了。我第一次调用 API，token 能拿到，但一写东西就被拒，就是因为权限没开、版本没发。

---

## 04 第三步：把应用加进你的知识库（最容易漏的一步）

朋友们，**这一步我真的要重点说**，因为 90% 的人卡在这里，而且卡得莫名其妙。

**具体操作：**

第一步，在飞书里打开你要存内容的那个知识库（我的是「海外案例」）。

第二步，点右上角的「…」→「设置」→「成员管理」。

第三步，点「添加成员」，注意了——**要切到「应用」这个标签页**，不是搜人的那个框！我第一次就是在搜人的框里搜了半天，怎么都搜不到。

第四步，搜你刚才建的应用名，权限选**可编辑**，保存。

**如果你搜不到应用名**，说明前面第三步的版本没发布、或者管理员还没审批通过。回去把这个搞定，再回来加成员。

> 💡 怎么验证加成功了？
> 你可以试着用 API 查一下这个知识库的信息，如果还是报错，就说明没加上。我当时就是反复查，发现应用能看到的知识库列表里根本没有我要写的那个库，才反应过来是加错地方了。

## 05 内容是怎么写进去的？

通路打通以后，写内容就有两种方式。

**方式一：手动复制粘贴**

篇数少的话（比如十几篇），直接在飞书里新建文档、复制粘贴，飞书会自动把 Markdown 转成好看的排版。够用了。

**方式二：用 API 批量写入（我用的这个）**

篇数一多，就必须走 API 了。我写了个脚本，干的事其实就三步：

1. **读本地的 Markdown 文件**，把标题、正文、表格、引用、链接都解析出来
2. **在知识库里创建一个文档节点**，拿到这个文档的 ID
3. **把解析好的内容按顺序写成飞书的内容块**，写完后记录一下「这篇写过了」

关键在第 3 步。飞书的文档内容是由一个个「块」组成的，标题是标题块、段落是段落块、表格是表格块。**你按块的格式写进去，排版就是原生的**，而不是一大坨文本。

我的 183 篇就是这么跑完的：**12 分 35 秒，全部成功，一个都没失败**。

每篇的结构是固定的：开头一张「案例档案」表（一句话定位、营收模式、月收入、流量来源、数据来源、原文链接），下面是完整正文。别人打开一看，信息密度很高，一眼就能抓住重点。

> 🔧 想省事的话：现在有很多 AI 编程工具（比如 CodeBuddy、Cursor），你把需求说清楚，让它帮你写这个脚本就行，不用自己从零写。

## 06 我踩的三个坑（帮你省两小时）

这部分是我实际撞过的墙，朋友们收藏好，能省你不少时间。

**坑一：报错 `131006 permission denied`**

意思是「没有权限」。99% 是上面第四步没做——应用没被加进知识库，或者加的时候选的是「人」不是「应用」。

回去把应用加进知识库成员，给可编辑权限。

**坑二：报错「field validation failed」**

飞书写入内容块时，有两种模式：老的 `children` 模式，和新的 `descendants` 模式。

我一开始用的是 `children`，连普通段落都写不进去，一直报校验失败。后来换成 `descendants` 模式（每个块先起个临时 ID，一次性提交）就全通了。

**结论：直接用 `descendants` 模式，别在 `children` 上浪费时间。**

**坑三：表格建不出来，报 `invalid param`**

这个坑最阴。我建表格的时候，给表格属性里加了个 `merge_info: []`（空的合并单元格配置），结果整个请求直接挂掉。

删掉这个字段就好了。

**结论：表格属性只留 `row_size`、`column_size`、`column_width`、`header_row` 这四个，多余的字段一个都别加。**

## 07 给你一条可以直接抄的路径

讲了这么多，最后给朋友们一条**可以立刻照着走的路径**，建议截图保存：

**① 想清楚存什么、存给谁看**
不是所有内容都值得存。我的标准很简单：**这篇内容我以后会不会想再翻出来？会不会想发给别人看？** 两个都不占的，别存。

**② 在飞书里建一个知识库**
按主题分，别按时间分。比如「海外案例」「AI 工具测评」「工作方法论」，一个主题一个库。

**③ 建应用 → 开权限 → 发版本 → 加进知识库**
就是上面第 02～04 步，这四步是一次性的，做完以后长期有效。

**④ 先把内容整理成 Markdown**
Markdown 是通用格式，从哪都能转到哪。如果你现在的内容在别的地方，先想办法导出成 `.md` 文件。

**⑤ 少量手动贴，超过 30 篇就上脚本**
别跟自己较劲。让 AI 帮你写脚本，你只需要说清楚：读哪些文件、写到哪个知识库、每篇写成什么结构。

**⑥ 写完回查一遍，别信脚本的日志**
我跑完以后又调飞书接口数了一遍：子节点数 183，跟预期一致，才敢说搞定了。**脚本说成功不等于真的成功**，一定要回查。

**⑦ 顺手在你的内容清单里打个勾**
我是直接在自己的案例表格里加了一列「同步飞书」，写完打 ✅。这样下次新增内容，一眼就知道哪些还没同步。
