## 一、部署站点（这部分很顺利）

### 1. 本地构建

关键点：**base 路径**。GitHub Pages 是子路径 `/case-site/`，自有域名是根路径 `/`。

```bash
cd /Users/hxw/codebuddy/case-site
rm -rf dist
npm run build -- --site https://shai3.top    # base 默认 /，site 覆盖成自有域名
```

输出 184 个页面，`dist/` 约 71MB（含大量封面图）。

### 2. 推送到服务器

```bash
ssh ubuntu@124.220.46.8 'sudo mkdir -p /var/www/case-site && sudo chown ubuntu:ubuntu /var/www/case-site && sudo chmod 755 /var/www/case-site'
rsync -az --delete dist/ ubuntu@124.220.46.8:/var/www/case-site/
```

### 3. 改 nginx：从「反代 8080」改为「静态托管」

原来 `shai3.top` 的 443 是 `proxy_pass http://127.0.0.1:8080`（刷题系统），改成静态托管：

```nginx
server {
    server_name shai3.top www.shai3.top;
    root /var/www/case-site;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }
    listen 443 ssl;
    ssl_certificate     /etc/letsencrypt/live/shai3.top/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/shai3.top/privkey.pem;
    ...
}
```

改前先备份：`sudo cp /etc/nginx/sites-available/shai3.top{,.bak.$(date +%Y%m%d%H%M%S)}`
改后：`sudo nginx -t && sudo nginx -s reload`

### 4. 停掉旧服务

```bash
pm2 stop quiz-app      # 只停止，保留 pm2 注册，可 pm2 start quiz-app 恢复
```

### 5. 验证

183 个案例页、封面图、http→https 跳转，全部 200。✅

## 二、第一个坑：证书正好在今天过期

**现象**：部署完一切正常，几小时后朋友反馈"这个不是 HTTPS 访问"。

**诊断**：

```bash
curl https://shai3.top/
# curl: (60) SSL certificate problem: certificate has expired

openssl s_client -connect shai3.top:443 -servername shai3.top | openssl x509 -noout -dates
# notBefore=Jun 14 03:12:34 2026 GMT
# notAfter =Sep 12 03:12:33 2026 GMT   ← 当天 03:12 到期
# 当前时间 03:39 → 已过期 27 分钟
```

**结论**：站点**一直配的是 HTTPS**，不是配置问题——只是 Let's Encrypt 证书 90 天到期，恰好在部署后几小时过期。之前验证时还没到期，所以当时是好的。

> 教训：证书过期是"定时炸弹"，验证通过不代表明天还通。

## 三、第二个坑：证书续不上（真正麻烦的地方）

### 尝试 1：`certbot renew` —— 失败

```
Domain: shai3.top
Type:   unauthorized
Detail: 43.174.224.202: Invalid response from
        https://dnspod.qcloud.com/static/webblock.html?d=shai3.top
```

Let's Encrypt 的验证请求被劫到了 **DNSPod 的域名阻断页**。

### 排查 A：是我的 nginx 配置问题吗？

查访问日志，发现 LE 的请求**确实到达了 nginx**，但响应不对：

- 大量返回 `301`——被 80 端口的跳转规则拦走了
- 少数返回 `200` 但内容是 **106KB 的 HTML**——被 `try_files ... /index.html` 兜底成了首页

**根因**（这个坑很隐蔽）：Certbot 生成的 80 端口配置长这样：

```nginx
server {
    if ($host = shai3.top) {          # ← server 级 if
        return 301 https://$host$request_uri;
    }
    listen 80;
    ...
}
```

nginx 的 **server 级 `if` 在 location 匹配之前执行**，所以即使你单独配了 `location /.well-known/acme-challenge/`，也会先被 `return 301` 弹走。证书一旦过期，跳到 https 就必然失败——**形成死锁**。

**修复**：把跳转从 server 级 `if` 挪进 `location /`，挑战路径用独立 location 放行：

```nginx
server {
    listen 80;
    server_name shai3.top www.shai3.top;

    location /.well-known/acme-challenge/ {   # 挑战路径直接应答，不跳转
        root /var/www/certbot;
        default_type "text/plain";
    }

    location / {
        return 301 https://$host$request_uri;
    }
}
```

自测通过：`curl -H "Host: shai3.top" http://127.0.0.1/.well-known/acme-challenge/probe` → `200 test-ok`

### 排查 B：还是失败 → 查 DNS 有没有问题

```
权威 NS (dnspod)   → 124.220.46.8 ✅
1.1.1.1 / 8.8.8.8  → 124.220.46.8 ✅
119.29.29.29(腾讯) → 124.220.46.8 ✅
223.5.5.5(阿里)    → 124.220.46.8 ✅
```

**DNS 完全正常**，不是解析问题。

### 尝试 2：TLS-ALPN（走 443 端口）—— 也失败

```
None of the preferred challenges are supported by the selected plugin
```

certbot 1.21 的 standalone 插件不支持 tls-alpn-01。

### 定性：根因是域名未备案

`dnspod.qcloud.com/static/webblock.html` 是**腾讯云对"未备案域名指向国内服务器"的标准阻断页**。

- 域名 `shai3.top` **未做 ICP 备案**（已确认）
- 腾讯云封堵了该域名的 80 端口 → Let's Encrypt 的 http-01 验证**永远走不通**
- 但**普通用户访问是通的**（日志里外部 IP 正常取到图片），只有 LE 的验证请求被拦

## 四、解法：改用 DNS-01 验证

### 原理

http-01 是"在网站上放个文件让 LE 来下载"→ 需要 80 端口。
**DNS-01 是"在 DNS 里加一条 TXT 记录让 LE 来查"** → **完全不碰 80 端口**，未备案也照样能签。

### 工具选型

certbot 没有官方 DNSPod 插件 → 用 **acme.sh** + `dns_dp`（DNSPod API）。

### 安装（国内服务器的坑）

`get.acme.sh` 官方脚本会从 GitHub git clone，**国内服务器极慢/卡死**。

acme.sh 本质是**单文件 bash 脚本**，改用 jsDelivr CDN 直接下载：

```bash
sudo curl -sL -o /root/acme.sh https://cdn.jsdelivr.net/gh/acmesh-official/acme.sh@master/acme.sh
sudo chmod +x /root/acme.sh
sudo /root/acme.sh --install --home /root/.acme.sh --accountemail admin@shai3.top
sudo cp /root/acme.sh /root/.acme.sh/acme.sh    # 补上（安装脚本拷贝会失败）
```

插件：`/root/.acme.sh/dnsapi/dns_dp.sh`（DNSPod，用 `DP_Id`/`DP_Key`）
备选：`/root/.acme.sh/dnsapi/dns_tencent.sh`（腾讯云 CAM，用 `Tencent_SecretId`/`Tencent_SecretKey`）

### 密钥安全（重要）

DNSPod 的 API Token 只能改 DNS 解析，**碰不到服务器和数据**，比腾讯云 CAM 主账号密钥安全得多——所以选它。

- ⚠️ 如果要用 CAM 密钥，**务必建"仅 DNS 权限的子账号"**，主账号全权限密钥等于交出整个云账号
- 密钥建议写入 `/root/.dnspod_token`（权限 600），不要放在命令行历史里
- **密钥一旦在聊天/文档中出现过，就该去控制台轮换**

### 一键脚本 `/root/issue-cert.sh`

会自动识别两种密钥，完成：签发 → 安装到 `/etc/letsencrypt/live/shai3.top/` → 恢复 443 配置 → reload nginx。

```bash
sudo sh -c 'printf "DP_Id=你的ID\nDP_Key=你的Token\n" > /root/.dnspod_token; chmod 600 /root/.dnspod_token'
sudo /root/issue-cert.sh
```

### 结果

```
subject=CN = shai3.top
notBefore=Sep 12 04:21:51 2026 GMT
notAfter =Dec 11 04:21:50 2026 GMT
HTTP/1.1 200 OK
```

自动续期：acme.sh cron 已写入 root crontab（每天 1/7/13/19 点检查），`certbot.timer` 已停用避免冲突。

## 六、坑点总结（下次直接看这里）

| # | 坑 | 根因 | 解法 |
|---|---|---|---|
| 1 | 部署完几小时站点变"非 HTTPS" | 证书恰好当天 03:12 到期 | 到期前 30 天就该续；`certbot.timer` 要确认真的能跑通 |
| 2 | `certbot renew` 报 unauthorized | server 级 `if ... return 301` 先于 location 执行，挑战被跳走 | 跳转挪进 `location /`，挑战路径独立放行 |
| 3 | 挑战返回首页 HTML 而非 token | `try_files ... /index.html` 兜底 | 同上，配合 webroot |
| 4 | 修好 nginx 仍失败 | **域名未备案**，腾讯云封 80 端口（DNSPod webblock） | 换 **DNS-01** 验证，不依赖 80 端口 |
| 5 | TLS-ALPN 也不行 | certbot 1.21 standalone 不支持 | 用 acme.sh |
| 6 | acme.sh 安装卡死 | 国内服务器拉 GitHub 慢 | 走 jsDelivr CDN 下单文件 |
| 7 | 挂着过期证书的 443 导致浏览器硬拦截且不回落 http | 浏览器安全策略 | 应急时摘掉 443，让浏览器自动回落 |

## 七、遗留事项与建议

1. **轮换 DNSPod Token**：本次的 ID/Token 出现在了对话记录中，去 DNSPod 控制台删除重建，更新 `/root/.dnspod_token`
2. **建议做 ICP 备案**（免费，个人主体 7–20 天）：
   - DNS-01 只解决了"拿证书"，**没解决未备案本身**
   - 腾讯云随时可能直接封 80/443，届时不是证书过期，而是**站点彻底打不开**
   - 备案后 80 端口解封，可换回常规 certbot
3. **服务器安全**：`:631`（CUPS 打印服务）对外监听且与网站无关，建议防火墙关掉
4. **两套部署并存**：GitHub Pages（`ASTRO_BASE=/case-site/`，push 即自动部署）与 shai3.top（base=`/`，手动 rsync），**base 不同别混淆**
